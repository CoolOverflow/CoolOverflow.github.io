FamicomSimulator

C# 手写 6502 CPU 与 PPU，从零实现可跑测试 ROM 的 FC 模拟器

照着 nesdev wiki 和 StepFC 的思路，用 C# 从 6502 指令、寻址模式一行行写起，再补 PPU 的扫描线与精灵渲染，最后用 OpenTK 开窗口出画面。仓库里带着 nestest 与 colortest 两个 ROM，方便逐指令对拍，调通那一刻确实是模拟器最有成就感的瞬间。

  • 模拟器

TinyRendererLearn

手写软件光栅化渲染器，实现 Gouraud、法线贴图与阴影贴图

ExcelAsPixelShader

把 Excel 单元格当像素，用 VBA 宏跑光线步进，慢到离谱

看到“Excel 也能当 GPU”的脑洞后动手验证：把每个单元格当一个像素，用 VBA 宏在单元格上跑光线步进，算完直接刷单元格背景色。画面确实能出来，代价是算一张图要等很久——但也算用最笨的方式体会了一次并行度对渲染性能的意义。

游戏引擎 C#

UnityParticleSystemMemoryOptimization

用粒子系统池加配置类复用，压掉 Unity 粒子反复实例化的内存开销

照 Unity 官方性能指南做的实验：不再给每种特效各存一个粒子系统，而是用通用对象池 + 一个配置数据类，需要时把参数刷到对象上。实测粒子系统内存从 65.7M 降到 16.7M 配置 + 10.7M 场景，也顺带记下了“停用不释放、只有销毁才回收内存”这个容易踩的坑。

  • Unity
  • 性能优化
  • 内存

SimpleFluidSimulation

用元胞自动机、SPH 与 SDF 渲染三种思路实现流体模拟

把流体模拟的几条常见路线各写了一遍：元胞自动机用格子演化，最短平快；SPH 给粒子加核函数算密度、压强和粘性；第三版干脆把粒子场当 SDF 交给渲染。三个脚本都带结果 GIF，适合横向看不同方法在效果和开销上怎么取舍。

ShadertoyNNImage

把神经网络权重翻译成 GLSL 常量，用着色器实时还原参考图

先跑 main.py 训练一个小网络逼近参考图，再用 model_to_c.py 把权重导出成 C 代码，直接粘进 Shadertoy 片段着色器。图像不再是贴图，而是一组长到离谱的常量。训练和渲染因此拆成两条能分别验证的链路，也算亲手摸了一次“权重即数据”的边界。

CSharpPersudoRandom

可按索引取值的伪随机数，任意下标都能复现同一随机序列

System.Random 只能顺序取数，没法直接问“第 1024 个随机数是多少”。这个实现换成按索引取值，任意下标都能直接算出同一个结果；README 里还附了用反射存取 System.Random 内部状态的办法，方便老项目不改调用点就能存档和恢复随机序列。
